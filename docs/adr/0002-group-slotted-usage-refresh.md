# 0002 - 用量刷新按组错峰

`/usage` 有独立限流（官方 10 次/10 分钟，按 Key），且固定出站 IP 上的流量形态本身就是要管理的信号——组的存在理由就是控制使用节奏。决定：保持每 Key 每周期一次的总量不变，把时间形状从「10 连发」改为「组为槽」：周期按组数均分，槽内成员一起刷新、组间错开，槽边界 ±10%、槽内每 Key 0–10s 随机抖动；三个刷新入口（定时槽、重建后的补刷、Research 结算）共用每 Key 节流——成功等一个周期、非 429 失败等 2 分钟、429 等 max(Retry-After, 300s)；启动时的全量刷新是唯一例外，并作为节流起点。

## Considered Options

- 缩短周期换新鲜度：IP 总量成倍上升，与「安静」目标背离（外部调用源的存在已明确为「假设存在、不过于重视」）。
- 只刷活动组：违背「全部 Key 要求新鲜」——外部调用源的消耗只有快照能看到。
- 池级预算（全池共享每 10 分钟 N 次）：与按 Key 的限流形状不符，会把健康 Key 串在共享计数器后面。

## Consequences

- 重建分组会重排槽位；Key 数据陈旧度上界约为一个周期。
- Research 结算的即时对账可能顺延到下一个槽。
- 验收只认可测指标：近周期请求总数、60 秒最大连发、10 分钟 429 计数（`docs/superpowers/specs/2026-09-15-group-slotted-usage-refresh-design.md`）。
